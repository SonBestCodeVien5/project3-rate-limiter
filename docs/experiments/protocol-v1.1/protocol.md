# Project 3 formal study protocol v1.1

**Status: locked plan; T09 execution is authorized. Stop after T09; T10 is not authorized by this request.** This is an operational revision of locked protocol v1. It keeps the same 46 scientific cells, 138 planned slots, three repetitions, 30-second durations, workload and topology values, run order, and frozen recovery thresholds. It changes invocation handling, quality-gate callbacks, and replacement-path bookkeeping. The measurement-tool changes are committed at the manifest source pin. A bounded stage-1 smoke verified the standard runner, both policy-specific outage pairs, fixed-threshold analysis, and stop-before-pause behavior for an invalid healthy run ID. The smoke did not start a formal matrix run.

The project question and limits are unchanged: compare distributed rate limiting for a multi-instance API, including a mixed legitimate/abusive backend-protection baseline and a bounded Redis outage. Results describe this prototype and its controlled workload, not a real retailer or production availability. See [locked v1](../protocol-v1/protocol.md) for the scientific rationale, limitations, and reporting boundaries; v1 remains immutable historical evidence.

## What changed operationally

V1 grouped both outage policies in one runner invocation. V1.1 uses one invocation per policy and repetition, so each callback can identify that policy's healthy and outage run and apply the quality checker immediately after each phase. There are 126 standard invocations and six outage pair invocations, 132 invocations total. The outage pairs are ordered open then closed in each of the three blocks; each pair runs healthy first, then runs its matching outage only if the healthy gate passes. The planned rows retain all four outage phases per block.

The v1 manifest allowed at most two replacement attempts per non-outage cell and two paired replacements per outage policy; v1.1 makes these limits explicit as **two total replacement attempts per non-outage cell across the whole study** and **two total paired replacements per policy across the whole study**. These are caps, not quotas. Preserve every attempt. A replacement gets a new output root by appending `.attempt-N` to its planned output path, where `N` is a fresh attempt number. Never overwrite an output. The execution ledger records the actual case directory for every attempt; quality checks and the final result manifest use that actual path, including for replacements. The accepted results manifest contains only the three valid attempts selected for each cell, while all failed/replaced attempts remain available as evidence.

The runner command rows contain `<ABSOLUTE_PROTOCOL_V1_1_MANIFEST>` as a placeholder; the coordinator substitutes the absolute main protocol manifest path. The coordinator runs `python3 <PINNED_CLONE>/scripts/run-study.py --manifest <ABS_MAIN_DOC_MANIFEST> --output <FRESH_EXTERNAL_RESULT_DIR>` and adds `--resume` only for a resume. Raw artifacts stay under the pinned clone ignored `artifacts/protocol-v1.1`; the ledger and results stay in the external output directory.

The manifest retains the v1 cell values and ordering exactly. Its measurement source pin is `0291a80fb404fea0eafee8c3431acc3631bb423e`, a helper-only runner/checker revision based on v1 source `b090d2b7391db873a0a2bbe602321ed1f5a55691`; no application or workload behavior changed. A checker-only correction scopes the no-overload tooling gate to the actual normal block; scaling at 250 RPS retains its intended backend-bound outcome. The protocol document/manifest commit is separate from the pinned measurement source revision. V1.1 continues to use only the T07 frozen recovery thresholds: open 81.9048105 ms and closed 82.577208 ms, with 1,000 ms windows, at least five legitimate samples per window, and three consecutive clean windows. Do not recompute or tune them.

## V1 operational gaps and validation

V1 is not rewritten. Its plan used one outage invocation for open and closed, which could not express separate policy-specific quality callbacks or independently identified runner run IDs. Its replacement policy was worded less explicitly for these requested study-wide caps, and its planned rows named only initial result paths. V1.1 records distinct policy invocations and actual-attempt paths so failed runs can be retained without path reuse.

The [T09 smoke worklog](../../worklog/2026-10-20-t09-smoke/README.md) records the bounded validation. Standard `p1-003-normal-none-r1` passed; open and closed policy callbacks passed their healthy/outage checks, while an invalid healthy run ID stopped before pause or outage creation. A real copy of the closed pair was reanalyzed offline: dynamic analysis bytes were preserved, fixed threshold 82.577208 ms was recorded separately, and the final `0291a80` checker accepted it. Mocked coordinator tests exercised replacement-path handling; a live retry was not part of smoke. No formal matrix run started. The 90-second observer passed with zero >5 ms steps, but a fresh observer is required before measurement. Guest BOOTTIME-to-MONOTONIC checks detect suspension accounted by the guest; a hidden WSL host pause remains unverified. The smoke archive and its SHA-256 are recorded in the manifest.

## Planned artifact layout

Standard first attempts live under `artifacts/protocol-v1.1/<planned-run-id>/custom-repeat-1`. Outage first attempts have separate policy-specific roots (`outage-open-rN` or `outage-closed-rN`), each storing that policy's `healthy/` and `outage/` cases. This makes the output path itself identify both policy and repetition. Replacement roots append `.attempt-N`; preserve both the case path and parent run evidence in the execution ledger. All paths are under ignored `artifacts/` and outside this documentation tree.

After measurements exist, create a distinct report-study result manifest under `docs/experiments/protocol-v1.1/results/manifest.json`. Planned paths resolve relative to this results manifest: four directory levels up reach repository root, followed by `artifacts/protocol-v1.1/...`. For a replacement, use the actual case path recorded in the external ledger. Keep the planning manifest unchanged.

The unchanged matrix is 5 normal, 5 burst, 5 mixed-overload, 27 scaling, and 4 bounded-outage cells. The total offered-load baseline is 4,140 seconds. With two replacements for every non-outage cell and two paired replacements per outage policy, the maximum is 6,900 offered-load seconds across at most 230 phases. The run order, host/clock gate, measurement validity conditions, Redis network-counter semantics, T06 RQ4 evidence boundary, and T07 recovery analysis remain as recorded in v1.

T08 network measurements have strict limits: Redis byte deltas include sampler INFO calls, healthchecks, and administrative queries as well as workload traffic; the observed sample interval was 2.29–2.42 seconds despite a one-second sleep; one paired run showed sampler contamination but did not support an overhead correction or a latency conclusion. Outage runs do not sample Redis resources. Report those counters as total Redis traffic over the observed interval, never as limiter-only bytes/request or wire overhead.


Phase failures and host suspension remain attempt boundaries. Preserve phase-specific evidence, stop after a guest/host suspension for observer and clock review, and continue only within the listed replacement caps; never reuse an output directory.
