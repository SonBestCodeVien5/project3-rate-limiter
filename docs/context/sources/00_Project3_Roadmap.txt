Project 3 Context Document - Distributed Rate Limiting Roadmap
Mục đích: Tài liệu nền để tham chiếu khi phát triển Project 3 và định hướng Đồ án tốt 
nghiệp.
1. Background và mục tiêu dài hạn
Project 3 được định hướng là bước chuyển từ việc xây dựng một hệ thống phần mềm hoàn 
chỉnh sang nghiên cứu và giải quyết một vấn đề kỹ thuật có tính mở rộng, hiệu năng và vận 
hành thực tế.
Định hướng tổng thể:
Project 2:
Xây dựng một hệ thống backend/application hoàn chỉnh.
↓
Project 3:
Nghiên cứu khả năng mở rộng, reliability và performance của hệ thống backend.
↓
Đồ án tốt nghiệp:
Phát triển thành hệ thống hạ tầng backend hoặc nền tảng traffic management có quy mô lớn 
hơn.
2. Liên hệ với Project 2
Project 2 là hệ thống Gym Management System, tập trung vào việc xây dựng một ứng dụng 
nghiệp vụ hoàn chỉnh với backend API, database, authentication, frontend và deployment.
Project 3 không tiếp tục mở rộng theo hướng thêm nhiều chức năng nghiệp vụ, mà tập trung 
đào sâu các vấn đề thường xuất hiện khi hệ thống phát triển lớn hơn:
- khả năng mở rộng;
- xử lý lưu lượng lớn;
- tính ổn định;
- bảo vệ hệ thống trước traffic bất thường.


Từ kinh nghiệm xây dựng backend trong Project 2, Project 3 chuyển hướng sang góc nhìn 
của một backend/system engineer.
3. Problem statement - Góc nhìn doanh nghiệp
Doanh nghiệp vận hành các hệ thống API phục vụ nhiều người dùng thường phải đối mặt 
với lượng truy cập không ổn định.
Các tình huống:
- chiến dịch marketing;
- flash sale;
- lượng người dùng tăng đột biến;
- bot hoặc request bất thường.
Nếu không có cơ chế kiểm soát traffic phù hợp, hệ thống có thể:
- quá tải CPU/memory;
- tăng latency;
- gây lỗi dịch vụ;
- ảnh hưởng tới toàn bộ người dùng.
4. Business requirement
Doanh nghiệp cần một lớp kiểm soát nằm trước backend có khả năng:
- giới hạn request theo user/API key/IP;
- hoạt động trong môi trường nhiều API instance;
- chia sẻ trạng thái giữa các server;
- đảm bảo tính chính xác;
- hạn chế tạo thêm bottleneck.
5. Đề tài Project 3
Tên đề tài:
Nghiên cứu và xây dựng cơ chế kiểm soát lưu lượng phân tán cho hệ thống API nhiều 
instance.
Tên tiếng Anh:
Research and Development of a Distributed Traffic Control Mechanism for Multi-instance 
API Systems.

7. Core research focus
Các vấn đề nghiên cứu:
1. Rate limiting algorithms:
- Fixed Window.
- Token Bucket.
- Sliding Window (mở rộng).
2. Distributed state:
- Local state.
- Redis shared state.
- Atomic operation với Lua Script.
3. Scaling:
- Single instance.
- Multiple API instances.
4. Evaluation:
- Correctness.
- Latency.
- Throughput.
- Resource usage.


8. Scope Project 3 (10-11 tuần)
Implementation:
- API instances.
- Load balancer.
- Redis shared state.
- Rate limiter.
Experiments:
- Normal traffic.
- Burst traffic.
- Concurrent requests.
Metrics:
- p50/p95/p99 latency.
- Requests per second.
- Overshoot rate.
- Redis CPU/memory.
