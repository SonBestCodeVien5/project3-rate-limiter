1. Bối cảnh doanh nghiệp
Ngày nay, nhiều doanh nghiệp cung cấp dịch vụ thông qua hệ thống API. Khi số lượng 
người dùng tăng lên, hệ thống backend thường được mở rộng từ một máy chủ đơn lẻ thành 
nhiều instance để tăng khả năng xử lý.
Tuy nhiên, kiến trúc nhiều instance tạo ra vấn đề mới trong việc kiểm soát lưu lượng truy 
cập và bảo vệ hệ thống.
2. Vấn đề doanh nghiệp gặp phải
Lượng request có thể tăng đột biến trong các trường hợp như chiến dịch quảng cáo, ra mắt 
sản phẩm, traffic bất thường hoặc bot request.
Hậu quả:
- CPU và memory tăng cao.
- Database bị quá tải.
- Response time tăng.
- Dịch vụ không ổn định.
Trong môi trường nhiều API instance, việc giới hạn request trở nên khó khăn vì trạng thái 
rate limit không được chia sẻ giữa các máy chủ.
3. Nhu cầu của doanh nghiệp
Doanh nghiệp cần một lớp bảo vệ trước backend có khả năng:
- Kiểm soát request trước khi xử lý.
- Hoạt động trong môi trường nhiều instance.
- Chia sẻ trạng thái giữa các server.
- Đảm bảo tính chính xác của giới hạn request.


4. Giải pháp đề xuất
Đề tài nghiên cứu và xây dựng Distributed Rate Limiting System.
Thành phần:
- Load balancer mô phỏng traffic distribution.
- API instances.
- Redis làm shared state storage.
- Rate limiting mechanism.
5. Câu hỏi nghiên cứu
RQ1: Các thuật toán rate limiting ảnh hưởng thế nào tới latency, throughput và burst traffic?
RQ2: Distributed shared state ảnh hưởng thế nào tới correctness và performance?
RQ3: Khi tăng số lượng API instance, hệ thống thay đổi thế nào?
RQ4: Atomic operation như Redis Lua Script có cải thiện correctness trong môi trường 
concurrent request không?

11. Lý do lựa chọn đề tài
Khi hệ thống backend chuyển từ mô hình đơn máy chủ sang kiến trúc nhiều instance, bài 
toán quan trọng không chỉ là xây dựng chức năng mà còn là đảm bảo khả năng mở rộng, ổn 
định và tự bảo vệ trước biến động lưu lượng.
Distributed Rate Limiting là một bài toán thực tế trong các hệ thống phần mềm hiện đại và 
là nền tảng để phát triển các hệ thống API Gateway, Traffic Management trong đồ án tốt 
nghiệp.
