# T06 — concurrent atomicity evidence

Task: T06, RQ4. This is focused integration evidence, not a performance benchmark.

At source revision `26b5decb835dbb136eb2d45b361920a414434f6b`, the existing tests exercised concurrent requests through three independent Redis limiter objects sharing one run namespace. Fixed Window admitted exactly the quota within each observed Redis-time window; Token Bucket admitted exactly its configured capacity. The existing non-atomic control used a barrier to force 16 readers to observe counter 0 for quota 1; all 16 considered themselves admitted, while last-write-wins left stored counter 1 (forced overshoot 15).

Added `TestRedisConcurrentNearExhaustedQuota` for both Fixed Window and Token Bucket: preconsume 8 of 10 units, then issue 16 concurrent requests. Exactly the remaining 2 were allowed for each algorithm. The Fixed Window case compares every concurrent Redis decision timestamp with the preconsume window. If Redis TIME shows a boundary crossing, it marks the quota assertion inconclusive with an explicit skip instead of reporting a quota failure. Token Bucket refill is negligible during the test.

Focused check: Focused near-exhausted follow-up: `GOCACHE=/tmp/p3-go-cache REDIS_TEST_ADDR=127.0.0.1:16380 go test -race ./internal/limiter -run '^TestRedisConcurrentNearExhaustedQuota$' -count=1 -v` — PASS for both algorithms. The final combined focused set also passed; exact command and captured stdout are in [artifacts](artifacts/COMMAND.txt) and [focused-final.log](artifacts/focused-final.log). SHA-256 values are in [SHA256SUMS](artifacts/SHA256SUMS). It ran against a dedicated temporary `redis:7-alpine` container named `p3-atomicity-20261019`; the container was removed after the run. Limits: the barrier deliberately forces a lost-update interleaving; it says nothing about natural race frequency. These tests do not compare HTTP performance or measure Redis CPU/throughput. They establish quota invariants for the tested Redis scripts and workload only; timeout-after-script ambiguity and host-wide performance remain outside this evidence.
